## Public API and ownership

New `factors/arc_source_events.hpp/.cpp` declares `ArcCloneConfig`, `ArcSourceEvent`, counts and read-only diagnostic value types. `validateArcSourceEvents`, `validateArcCloneConfig`, `readArcSourceEvents`, `arcSourceTimeBits` are the parser contract. Source CSV remains the plan's 12 columns, version 1; exact source double/IEEE754 bits/replay equality and unknown actual arrival are mandatory. Configuration availability policy is lowercase `source_time_replay_assumption`; event availability mode is uppercase `SOURCE_TIME_REPLAY_ASSUMPTION`.

`GIEngine::setArcSourceEvents` is pre-initialize only; `finalizeArcSourceStream` records final coverage without propagation/output samples. Getters `arcJointPriors`, `arcLifecycleEvents`, `arcConditioningEvents`, `arcImuSegments`, `arcCloneCounts` expose const diagnostics. `writeArcCloneDiagnostics` serializes after finalization. `ArcNativeTestAccess` is a friend for the separate synthetic harness, allowing tests to exercise actual private END dispatch/current-only covariance guard and perturb state errors through real feedback; no public production covariance setter or alternative test-only algorithm is added.

`EKFUpdate` keeps three-argument compatibility, with optional source tag and provider identity. Existing production callsites now supply explicit tags. Actual selected RD/RP/HV/FGO provider rows carry the input vector index and source-time bits; GNSS carries exact native event-time bits with raw row identity explicitly unknown. These metadata do not establish physical source independence or phase-state cross covariance.

## Shared computational path

ARC and foot configuration are mutually exclusive. The shared 21+3 storage has an explicit NONE/FOOT/ARC owner. ARC uses only augmentation, ordinary joint updates, full feedback/reset, propagation of cross covariance, and current-marginal retirement. All existing foot pair models, intervals, H/R/epsilon/selection remain untouched. ARC mode enables the same full reset during gaps between clones in both empty-phase arms. Current-only covariance replacement is forbidden for either joint mode. Frozen zero blocks remain checked.

At an interior ARC source time the pre-existing exact split formula proportionally divides measured dt, dtheta and dvel; the source event adds no auxiliary update permission. At the current IMU end, ARC dispatch is deferred until the existing body-HV scheduler and its feedback complete. The corresponding START/END executes after all existing updates at that timestamp. START requires zero current errors; END requires zero current and clone errors. END records the conditioned clone nominal and current BLH/cbn after feedback, recomputes the position-sensitive J1, and computes B6 and P6 from the full P24, retaining every cross and frozen block.

Both arms compute and retain every complete snapshot and every common diagnostic. `LEGSA_ARC_NATIVE_TELEMETRY` is parsed as 0/1, then used only at the final writer branch controlling `ARC_JOINT_PRIORS.jsonl`. It does not gate mathematics, lifecycle, source selection, parameter values, diagnostics calculation or count logic.

## Explicit refinements of the proposal

1. Actual manifest integration is in `src/fileio/file_saver.cpp`, where this repository writes runtime manifest fields, rather than the plan's approximate `writers/port_writers.cpp` location. ARC is an independent input role `arc_source_time_metadata_only`; legacy/foot default manifest fields are unchanged.
2. Added `ARC_IMU_SEGMENTS.csv` and `arcImuSegments()` for every actual exact-event `insPropagation` input before compensation. This lets the new synthetic harness prove the production split's measured-increment conservation instead of mirroring a split formula. It is computed/written identically in both arms and must join the NAV/STD/lifecycle/conditioning byte-identity gate. It is a propagation-input log, not a sensor arrival log.
3. C++ validates the format of declared source/schedule SHA256 pins but has no internal file-hash implementation. Each prior explicitly states `DECLARED_PINS_EXTERNAL_RUNNER_VERIFICATION_REQUIRED` and `EXTERNAL_SEALED_RUN_RECEIPT_REQUIRED`. Root approved binding config/binary/provider hashes externally: the future runner must hash before and after execution and seal the same run/config/event paths and input pins. A matching run_id alone is insufficient. Native prior conditioning IDs bind declared schedule pins plus executed ordinary/reset/ledger prefix and exact state-time bits; they become a qualified run identity only through that sealed external binding.
4. All original blocks are represented in one lifecycle row from source ingestion. A final START with no source END is accepted only as an explicit terminal-uncovered block, never used to fabricate a pose; the real schedule prepare must still prove all 921 original START+END identities. Blocks starting at or before initial IMU support are `UNCOVERED_INITIAL_STATE`; otherwise pending/active blocks at finalization are `UNCOVERED_TERMINAL`. Covered END is `COVERED_END_PRIOR`. Original fingerprints are metadata and never admission gates.
5. Lifecycle dispatch phases default to `NOT_DISPATCHED`, and START/END dispatch phases are independent. Uncovered records retain missing dispatch as unknown rather than claiming completed conditioning. Planned owner ARC is separate from `clone_owner_at_creation` (NONE until real START) and `clone_created`. Partial START-only or END-only dispatch is explicitly named.
6. Common `start/end_state_sample_count` records completed exact-IMU output opportunities (the first initialization sample is excluded); END at an IMU end includes that output opportunity. It is not extra NAV output and not an availability proxy. The actual NAV sample count remains the runtime writer's sealed result.

## Limits and pending gates

No phase z/G/Q/integers, raw input or evaluation reference are read by the ARC module. Ordinary GNSS, IMU and SDK observations retain their inherited working covariance/source assumptions. Complete state-state cross does not imply known state-phase cross. The new interfaces do not reinterpret old SDK error-code quality gates or prove independent FK/body-velocity calibration.

The parser verifies safe IDs, stream identity, strict time order, no block overlap/reuse, endpoint uniqueness, matched ENDs and exact source bits; it does not certify hardware clock synchronization. Unknown arrival stays null in all new JSON and blank in CSV. Serialization is a diagnostic only; no PSD/information eigensolver or phase residual is invoked. New local tests, source freeze, independent review and the later matched NULL/TELEMETRY identity gate remain required. No claim is yet made that all 860 legal phase models have covered joint priors, or that any phase block adds heading/navigation information.
