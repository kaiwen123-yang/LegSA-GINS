# A2：20 s，九种子 × 全部 11 配置

本项包含 D62 的 99 个物理运行；v3/v2 是同运行的两个评价视图。RECORDED.csv 保存 198 行完整精度选定指标及原 JSON 行键；SCOPE.csv 保存实际注册窗口和种子。全部按 case_id/method_id 关联，不按文件行号配对。

99 个 native 终态和 198 个评价终态均为 `COMPLETED`，评价 `failure_classification=NONE`。本项是 BY2 同一实测输入上的 `semisynthetic` 注入，9 个种子对应中断位置，不是 9 次独立采集；v3/v2 也不是新增物理运行。A2 正式加项只注册 10 s 和 20 s，**A2 30 s 为 `NOT_REGISTERED`，不是 missing run 或失败槽**，不为它补造运行或纳入本项分母。参考为融合轨迹，不能因输出误差较小就称为独立真值。

已全文读取 [198 行原值](A2_20s_RECORDED.csv)、[60 行原 UA 统计/配对](A2_20s_UA_RECORDED.csv)、[396 个核对单元格](A2_20s_UA_CHECKS.csv)、[1,260 行逐例配对](A2_20s_PAIRED_CASES.csv)，以及注册、20 行 2×2、140 行配对算术和 provider 元数据。原值以 source_path、`source_row_key=run_id|v3或v2`、列名定位；UA 另保留原 CSV 的 `data_row_1based` 行键和十进制字符串，不用本轮算术覆盖原值。

## 输入变化与窗口

原加项定义来自 `clean6_addendum/providers.py::SOURCES/apply_outage`，但正式冻结输入还经过 `clean6_sensor_v21/providers.py::generate_case/correct_hv`（425–458、142–195 行）的重建链。实际窗口沿用 `_outage/_interval` 的半开 [start,end)；Protocol V3 的航向映射见 `docs/paper_rebuild/v3/PROTOCOL_V3_PREREG.md`。

A2 在窗口内移除位置、RV、RD 的有效性，保留按原始 BOTH_FIXED 规则有效的标量 heading；IMU、RP 和各 case HV 文件保留。

HV准备使用Go2自身source_valid与旧status航向插值支持的交集：unwrap线性插值不跨>1.2s长gap内部；body velocity经body roll/pitch与该旧航向旋转，update_flag承载有效性。V3只替换GNSS18观测文件中的heading/yaw_valid列，没有用新raw heading重建HV。本项已完整读九个明确bundle，PROVIDER_METADATA.csv逐字段保存yaw_before_HV、a1_valid_count、hv_valid_count及provider recorded hash/storage_mode；计数覆盖源序列，不冒充故障窗accepted_count。

九份实际小 bundle 均记录 `a1_valid_count=301`、`hv_valid_count=60867`、`yaw_before_HV=true`。HV、RP、IMU 是 `pinned_unchanged_pointer`，GNSS/RD 是 `materialized`；A2 没有给旧 status 航向增加停测，因此 HV 仍依赖旧准备链的航向支持，而非 Protocol V3 raw heading 新生成。301 和 60867 是整个 provider 范围计数，不是本 20 s 窗内的触发或接受次数，也不保证所有时间点都有合格行。[PROVIDER_METADATA.csv](A2_20s_PROVIDER_METADATA.csv) 保留原字段和 recorded hash，本项没有读取载荷或把 recorded hash 说成新校验。九个 bundle 各三个 `/components/0..2/details/interval` 都是对应单区间 pair，没有字典区间或额外恢复窗。

运行时至少一个GNSS position/velocity/yaw有效位为真才安排该事件，并在非basic路径中依次尝试RD/HV/RP （gi_engine.cpp 258–276、355–357、423–433）。HV自身还要求配置/solver_enabled、update_flag、active、truth_claim=false、时间容差内最近条目，随后可能被SA拒绝（1292–1362）；loader见go2_weak_prior_loader.cpp 181–270。它不是要求yaw_valid独自为真，也不等待RP当次被接受。因此A1三位全false时没有这条独立辅助调度入口；A2原有效heading历元可以触发事件，但仍受HV自身支持与门控约束。

HV配置开启、文件保留、存在有效行、触发调度和最终接受是不同门槛；仅凭误差曲线不能确定真实期间触发或接受次数。缺少在线接受/拒绝日志时，机制保持假设。A2 不能称完整 GNSS 拒止，也不能把期间收益归给已移除的 RD。

“保留 heading”仍受原 BOTH_FIXED 有效性及配置路径约束，不是人为令整个窗口航向始终有效。满足条件的 heading 可安排 GNSS 事件，此后 HV 时间匹配、source_valid/update_flag 和 SA 门控是否满足仍需独立记录；F01 也不会因输入存在 heading 自动变成持续航向更新。静态来源复用 [A2 10 s 说明](A2_10s.md)及已核实代码行号，本项没有重复执行准备链。
