# A2：10 s，九种子 × 全部 11 配置

本项包含 D62 的 99 个物理运行；v3/v2 是同运行的两个评价视图。RECORDED.csv 保存 198 行完整精度选定指标及原 JSON 行键；SCOPE.csv 保存实际注册窗口和种子。全部按 case_id/method_id 关联，不按文件行号配对。

99 个 native 终态和 198 个评价终态均为 `COMPLETED`，评价 `failure_classification=NONE`。这是 BY2 同一实测序列上实施故障注入的 `semisynthetic` 结果，9 个种子是 9 个注入位置，不是 9 次独立采集；v3/v2 不增加物理运行分母。参考为融合轨迹，不因为能计算小误差就成为独立真值。

本项实际全文读取 [198 行原值](A2_10s_RECORDED.csv)、[60 行原 UA 统计/配对](A2_10s_UA_RECORDED.csv)、[396 个核对单元格](A2_10s_UA_CHECKS.csv)、[1,260 行逐例配对](A2_10s_PAIRED_CASES.csv)，另有注册、20 行 2×2、140 行配对算术和 provider 元数据。原 JSON 以 source_path、`source_row_key=run_id|v3或v2`、列名定位；原 UA 保留原 CSV 的 `data_row_1based` 行键和十进制字符串。本轮算术与原表分列。

11 配置全部纳入：AB 四位依次 RD/SA/RP/HV；F03/A02=`0000`，F04/A01=`1111`，A03=`0111`，A04=`1011`，A05=`1101`，A06=`1110`，A07=`1100`，A08=`1000`，A09=`0100`。F01/F02 均为 `0000`；F01 无持续双天线航向更新且 RV 开，F02 是 basic 航向路径且 RV 关，其余 RV 开。共同航向初始化仍包含 F01，别名不重复计数。F04 为正式标量 R5/BOTH_FIXED；不是 B3。逐字段和 v3/v2 物理点、杆臂口径见[方法说明书](../METRIC_AND_METHOD_GUIDE.md)及 [METHOD_CONFIGS.csv](../METHOD_CONFIGS.csv)。

## 输入变化与窗口

原加项定义来自 `clean6_addendum/providers.py::SOURCES/apply_outage`，但正式冻结输入还经过 `clean6_sensor_v21/providers.py::generate_case/correct_hv`（425–458、142–195 行）的重建链。实际窗口沿用 `_outage/_interval` 的半开 [start,end)；Protocol V3 的航向映射见 `docs/paper_rebuild/v3/PROTOCOL_V3_PREREG.md`。

A2 在窗口内移除位置、RV、RD 的有效性，保留按原始 BOTH_FIXED 规则有效的标量 heading；IMU、RP 和各 case HV 文件保留。

HV准备使用Go2自身source_valid与旧status航向插值支持的交集：unwrap线性插值不跨>1.2s长gap内部；body velocity经body roll/pitch与该旧航向旋转，update_flag承载有效性。V3只替换GNSS18观测文件中的heading/yaw_valid列，没有用新raw heading重建HV。本项已完整读九个明确bundle，PROVIDER_METADATA.csv逐字段保存yaw_before_HV、a1_valid_count、hv_valid_count及provider recorded hash/storage_mode；计数覆盖源序列，不冒充故障窗accepted_count。

本组实际元数据与 A1 有区别：九例 `a1_valid_count=301`、`hv_valid_count=60867`、`yaw_before_HV=true`；HV、RP、IMU 均为 `pinned_unchanged_pointer`，GNSS 与 RD 为 `materialized`。A2 没有给旧 status 航向增加中断，冻结 HV 仍沿用该准备链的支持，不是利用 Protocol V3 新 raw heading 重新生成。301 和 60867 都是全 provider 范围计数，不能充作这十秒内 GNSS/HV 实际更新次数，也不能保证任意给定时刻都有合格 HV 行。[PROVIDER_METADATA.csv](A2_10s_PROVIDER_METADATA.csv) 保存原路径、字段及 recorded hash，本项没有读载荷或新校验 provider 哈希。九个 bundle 均只有三个注入组件，各 `/components/0..2/details/interval` 都是下表的单区间 pair，无字典区间或额外恢复窗。

运行时至少一个GNSS position/velocity/yaw有效位为真才安排该事件，并在非basic路径中依次尝试RD/HV/RP （gi_engine.cpp 258–276、355–357、423–433）。HV自身还要求配置/solver_enabled、update_flag、active、truth_claim=false、时间容差内最近条目，随后可能被SA拒绝（1292–1362）；loader见go2_weak_prior_loader.cpp 181–270。它不是要求yaw_valid独自为真，也不等待RP当次被接受。因此A1三位全false时没有这条独立辅助调度入口；A2原有效heading历元可以触发事件，但仍受HV自身支持与门控约束。

HV配置开启、文件保留、存在有效行、触发调度和最终接受是不同门槛；仅凭误差曲线不能确定真实期间触发或接受次数。缺少在线接受/拒绝日志时，机制保持假设。A2 不能称完整 GNSS 拒止，也不能把期间收益归给已移除的 RD。

这里“保留 heading”指仍按原有效性规则提供该通道，不是把整个窗口强制设成航向有效。启用相关路径且原有效 heading 到达时，可以满足 GNSS 事件条件；随后是否有时间容差内的 HV、是否通过 SA、是否真正接受是后续独立条件。F01 的配置也不会因输入里有 heading 就变为持续航向更新方法。静态链及行号复用 [A1 10 s 已核实说明](A1_10s.md)，本项没有重复执行或重新选择输入。
