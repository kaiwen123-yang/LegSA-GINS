# CORE — Go2 弱先验与元数据（go2_prior_metadata）

本族包含 6 个退化类型（D51–D56）、每类型 9 个种子，共 54 个案例；11 个方法对应 594 个唯一 native，v3/v2 合计 1188 个评价槽。BY2 同一条原始轨迹上的半合成受控退化，不是这些数量的独立实测序列。失败行完整保留。

## 注入什么，保持什么

D51/D52 操作 RP 弱先验，D53/D54 操作 HV 弱先验；D55/D56 为 contact/motion/foot 元数据诊断。以 bundle 的 no_active_path 和组件回执识别元数据是否存在标量运行通路，不把诊断 case 当作已启用 contact/FK 因子。Go2 始终是弱先验/诊断源，不是真值；HV 仍继承原 status 航向旋转及有效性处理。

RP 的正式输入角色是 `go2_attitude_prior_path`，加载 `roll_rad/pitch_rad`、`std_roll_rad/std_pitch_rad` 和 `source_status` 等字段；它不是完整姿态真值约束，也没有启用 Go2 yaw/position 真值更新。HV 的角色是 `go2_horizontal_velocity_prior_path`，使用 NED 的 `vn/ve`、水平 std 及 `source_status/update_flag`，按 horizontal prior 处理。字段加载器也保留质量和接触标签，但“有标签”不能等同于存在足端运动学或接触因子。

| F01 | 0 | 0 | 无 |
| F02 | 0 | 0 | 无 |
| F03/A02 | 0 | 0 | 无 |
| F04/A01 | 1 | 1 | RP 与 HV |

已有 provider 的准备依赖也会影响解释。v2.1 准备代码对 RP 保留 Go2 roll、反转原 pitch 的符号，保留 1.6° 的冻结先验 std。HV 先把 Go2 body velocity 从 FLU 转 FRD，再用 Go2 body roll/pitch 与原 status/A1 双天线航向旋转到 NED，乘已冻结的 `1/0.962142`，水平 std 为 `0.132838 m/s`；航向使用 unwrap 后线性插值，支持边界及大于 1.2 s 的内部缺口控制有效性。Protocol V3 沿用这些 HV 字节，没有用新的 5 Hz raw HPPOSECEF 航向重做 HV。因此，关闭 RP 更新并不删除 HV 准备过程中对 Go2 roll/pitch 的依赖，HV 也不是与双天线航向完全独立的观测。

本族 D51/D52 只改 RP 的正式 provider；HV 旋转使用单独冻结的 body 支持数据，并未读取被注入的 RP 表来旋转。这与全部 18 份 bundle 的 HV recorded pin 保持原值一致。D53/D54 直接在已修正的 HV 基础表上注入，随后跳过会覆盖其数值的 HV 重建分支。以上是已存准备关系与源码语义，不是本轮重新运行准备代码。
