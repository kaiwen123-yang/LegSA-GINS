## 中断内到底有什么

原输入同时撤销position、RV、RD和heading有效性；HV又依赖既有准备航向。下表分母是中断内100个GNSS输入时点，时间条件均已到，不是逐IMU机会或所有provider行数。A04、F04读到相同候选资格结果：

|来源|创新前合格候选|合格但被GNSS入口阻断|实际函数入口|实际接受|
|---|---:|---:|---:|---:|
|position / RV / yaw（各）|0|0|0|0|
|RD|0|0|0|0|
|HV|0|0|0|0|
|RP|100|100|0|0|

RP不是仅`enable=true`：已有行满足匹配容差、active与正std等入口前资格，三GNSS位全假使整体入口不调度，故没有进入RP残差或更新函数。这是N09相关入口耦合的实际触发证据。它不证明放开入口后100次都会接受，也没有测试闭环误差收益。

RD虽有时间匹配行，其valid/质量条件不合格。HV在这些时点按原update_flag与容差找不到合格候选；不能并入RP的“有合格输入未调用”，也不能扩写为全部20 s的Go2速度行不存在。F03原本关闭RD/RP/HV，不给它记N09触发。具体row_id、dt、std及恢复边界见 [输入与调度细节](INPUT_AND_SCHEDULING_NOTES.md) 和 [完整小型调度表](SCHEDULING_COMPACT.csv) 的`run_id/window/source`键。
