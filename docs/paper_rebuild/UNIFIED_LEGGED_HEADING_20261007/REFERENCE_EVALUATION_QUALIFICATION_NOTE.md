# XB/NMB参考可信度与航向评价边界

2026-10-07，针对用户本轮重新询问高精度惯导参考用途。当前问题授权重新讨论其评价资格，但本轮未把标准轨迹或脚踝惯导接入算法/评价，未新增solver/evaluator，未修改历史误差。

## 当前核实事实

- 标准轨迹nmb.txt为151个六列数值点，xb.txt为149个。后三列逐点为前三列加初始位置，是同一路径的坐标平移，不是第二个独立解。
- 两TXT均无时间戳、姿态、速度、质量状态、设备型号、坐标系标识或测量点定义。XLSX只保留前三列；转换脚本还把字段行当作一行数据，因此有重复X/Y/Z表头。格式修正不能恢复不存在的时间/姿态。
- 未找到生成标准轨迹的原始处理链、与Fixposition同源/独立或同步的证据。FUSION列名不足以识别设备和算法。旧EXP01中的HIGH_CONFIDENCE_SPATIAL_ROUTE是脚本固定标签，不是精度认证。
- 最新SDK joint pilot PLAN明确参考来自Fixposition ZIP中的trace CSV，并声明reference_is_independent_ground_truth=false；未使用这两个标准轨迹。既有R5合同也明确与接收机系统共享GNSS信息。此为已核来源限制，不等于已经证明其所有时段都差或误差已有定量界。

## 能用什么参考评什么

同一时段、同一机体刚性共载、时间与安装/杆臂已知，并有实际质量依据的高等级GNSS/INS后处理解，可作为更强的PVA参考。仅有设备高精度称号、平滑轨迹或报告很小的内部协方差，不自动构成独立真值。共同GNSS来源仍可能产生共同错误。

如果标准轨迹是另一次沿同一路线测量，它最多提供空间路线/横向偏离对照。最近点距离混合真实走偏和导航误差，且可能掩盖沿轨误差；不能当逐时刻位置RMSE或航向真值。若是同一趟数据的稀疏导出，应先找回原始带时间、姿态与质量状态记录，再按同一物理点匹配。若设备在运动腿段上，机体到设备不是常量外参，不能使用常量杆臂/航向偏置换算机体真值。

位置、速度、航向应分别获得评价资格。位置可信而航向不可信时，仍可做位置对照；绝对yaw准确度及整数正确性无法由该参考证明。无可信航向参考的时段保留在可用率/失效时间轴，绝对航向误差结论标为无法确认，不按算法误差挑掉。

机体yaw与路径切线/course不同，尤其足式侧移、倒退、原地转向时。不能从标准XYZ微分生成机体yaw，也不能用同一待测gyro或同一短基线航向伪造独立参考。若独立刚性共载姿态设备只有初始方位不确定、短时旋转可靠，可以另评相对旋转/航向变化和锚点之间漂移，并明确没有解决绝对方位。长时漂移依然要计入参考不确定度。

高等级INS航向也取决于对准、传感器等级、运动及外援；低动态单天线GNSS/INS的航向可弱可观。可用独立双天线/经验证寻北或光学姿态作绝对锚，选择需适配实际平台。足式平台不能因为设备软件有汽车模式就默认零侧向速度。后处理平滑可用于离线参考，但不进入待测在线算法。

观测到的误差是算法误差与参考误差之差。局部角度线性化下Var(diff)=Var(algorithm)+Var(reference)−2Cov(algorithm,reference)；共享来源时不能简单从RMSE平方中减去参考方差。参考不确定度与所声称改善相当或未定量时，不能仅凭RMSE差确认真实精度排序。

## 对当前goal的影响

最新joint NULL/XYZ空窗H=4.654693/8.334093m等冻结数值保留。其严谨表述为“相对现行Fixposition参考未通过收益判据”，不是独立真实精度已被证明退化；也不能因参考可能不准就反过来宣布算法正确。足端—SDK来源内冲突、完整状态耦合、条件更新和撤销行为是另一层已验证事实。

先澄清标准轨迹是否同趟、同点与原始PVA/质量记录是否存在；参考可用时按其自身状态、对准、同步、安装和独立性分别限定position/heading支持。历史结果保留，若有合格新参考，则固定同一批NAV另开离线评价身份，不为换参考重跑算法，不以更有利的排名选参考。差分方向的数学/源内可辨识性工作仍可继续，但在参考资格未明确前，不再把未知真实误差的RMSE排名作为唯一模型修改依据。
