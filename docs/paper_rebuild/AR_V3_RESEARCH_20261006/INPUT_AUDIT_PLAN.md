# 同完整历史、同转换选项的输入诊断登记

目标是复现 HX02 的完整接收机历史与实际 convbin 参数，再比较旧 OBS。
仅用既有 V3 三序列六个接收机原始 CSV；不调用导航、整数解算或评价，不读取参考。
机器计划见 INPUT_AUDIT_PLAN.json；实际历史证据见 INPUT_EXTRACTION_DIAGNOSIS.json。

## attempt01 保留与修订

attempt01 在第一份 BY2_R1 转换前遇到两条长度矛盾的 UBX 同步字开头记录，
因强制所有记录合法而失败。原 STATE 原样保留为 input_history_attempt01_failure.json。
实际 convbin 调用为 0，六次预算全部尚未使用；此次修订不增加转换次数，不覆盖旧结果。

只读定位发现六流分别有 2/1/0/2/22/1 条同类记录，共 28 条。
它们均为 OTHER、class/id 0A06，实际 64 字节而头声明总长 128 字节。
按可见 64 字节计算尾校验一致，按声明长度跨到下一记录后校验失败。
不能由此确定硬件、传输或记录层物理原因，也不修复原始字节。
旧 HX02 有效帧扫描和旧 DG01R 截窗保留是不同的提取规则。

## 冻结提取与调用规则

1. 每个 raw 文件读取一次、校验原始哈希，按原 CSV 顺序串接所有 bytes cell。
   完整流用 HX02 原同步字、声明长度、checksum 与逐字节重同步规则；
   本地等价实现仅增加拒绝字节区间诊断，不改变接收规则，不修复原字节。
2. 逐条保存所有与拒绝区间相交的 CSV 行元数据、SHA、排除字节数和原因，
   另列 28 条长度/校验异常记录。扫描排除总字节还包含非 UBX 记录，
   不能把它直接称为损坏载波观测数量。
3. 截窗仅用于身份核对，保持 DG01R 原 inclusive 时间窗和同步字开头原样写入规则，
   包括其中异常记录；不把它作为本轮完整历史转换输入。
   完整、截窗 UBX 都必须先与各自历史哈希及字节内容匹配，否则停止。
4. 旧 LLI 表、六份完整 UBX、六份截窗 UBX 共 13 个新增 pin 全部来自历史封存。
   每次实际读入先记录 expected/actual SHA256 与 identity_equal，再校验；
   失败仍保留 STATE 和已完成结果。
5. 三个旧 NATIVE_OPENAT.strace 的六条成功 execve 与 RTKLIB_PREPARED.json 相符：
   convbin -r ubx -o OBS -n NAV UBX，除此之外没有 -v/-f/-od/-os。
   因而删除初始计划沿用的 DG01R 额外导出选项，使用相同已锁二进制和旧 HX02 参数；
   只替换输出/输入路径到同身份的新目录。六份旧 OBS 实际均为 RINEX 3.04，
   各系统有 2–5 个 C/L 类型，没有 D/S。头类型完整列表在诊断 JSON。
6. 六个输入各转换一次，单次 120 秒上限，无自动重试，不重新选择窗口。
   新输出必须写入新的 attempt 目录；attempt01 及所有旧数据不变。

## 一致性判定和结论边界

science_equal 同时要求历元集合一致、全部已解析观测字段无差异、RINEX 头语义一致、
科学记录正文一致。字段缺失也计差异；头包括有序 OBS TYPES、明确时间系统、
版本和观测解释记录。未声明时间系统保留 null；程序名、生成日期和注释不参与头语义比较。
正文一致不能独自替代科学一致。

旧 15 个 LLI 事件逐项报告 full_history_equal 和 old_full_table_consistent，
并单独汇总 all_old_lli_table_consistent。+18 秒是原登记时标映射的逆变换，
旧输入必须声明 GPS；新时间系统不一致时该事件不能冒充同一时刻比较。

COMPLETE / execution_complete 仅表示六项比较执行完成，不代表科学 PASS。
所有差异保留。完整输入与同选项输出一致只支持这条历史转换链的可复现性；
不能证明原始载波没有物理偏差、整数正确或导航算法优越。

所有运行在 Ubuntu-22.04 WSL 研究 scratch。原始文件、HX02/DG01R、V3 和 main 不写入。
