# 六个追加问题：研究判断与当前决策

本报告修正上一轮“值得花一周做速度解耦”的优先级判断。原有计算事实不变，但航向论文的研究价值必须由航向问题本身支撑，不能由一个完全GNSS失效位置指标代替。试验的工程继续门与论文创新门不是同一件事。

## 1. GitHub先合并：已经完成

[PR #63](https://github.com/kaiwen123-yang/LegSA-GINS/pull/63)已合并main，保留427个提交历史，merge commit为6c2ba735b85c0030e8b730ad675ebbc55e741ffa。旧PR #62也因提交已被包含而自动标记合并。主分支不再停留在早期状态。

论文原V3的源码、runner、binary与6468项结果仍按原冻结身份识别。合并研究仓库不等于将后来的诊断源码追认成原V3。后续航向/FIX检查和本轮隔离试验在独立研究分支完成，正式生产源码保持原样。

## 2. 是否继续速度解耦：下调为附属工程问题

用户对上一轮建议偏积极的质疑成立。它在完全GNSS失效的一个固定事件中有很大的水平收益，但主要证明“原来停掉的本体信息现在还能进入滤波器”。这不足以决定以航向为核心的论文应投入一整周升级，尤其原候选垂向恶化、保留航向时水平误差略差。

新的机体系速度观测本身不提供绝对航向。若GNSS位置/速度也缺失，在局部重力模型下，将水平速度与航向一起旋转仍保持body速度观测不变；不能把它称为断星绝对航向恢复。若GNSS NED速度仍在、仅双天线方向来源丢失，运动中的body速度与NED速度可以间接约束航向。本轮H20保留位置/RV，但同时移除航向源及依赖它的旧HV插值支持，结合D61/D62检查不同信息可用性；它不是仅删除一条yaw测量的纯单因素对照。静止/低速和无可靠初始航向仍需另立条件。

当前决定：保留原V3论文版本，不启动整周足式里程计改造。速度解耦只作为已发现调度问题的工程候选，是否采用须看独立序列、源语义和实际航向需求，不因一个好结果而扩大主线。

## 3. 三项贡献是否够：不能靠换名字补出方法

我的判断是：现有三项可组织为系统贡献，但作为“三个新算法”偏弱。短基线位置差求航向、SDK弱辅助、标准EKF和一般质量门控都已有基础。大量运行、漂亮RMSE与新颖性是不同证据；同一录制的注入重复也不增加独立场景数。

GPS Solutions的方向匹配较强，但我不认为仅凭“短基线+机器狗+KF-GINS”就能肯定贡献充分。需要明确一个导航测量问题、实质处理机制及相同信息下的可迁移收益。TIM还要求主要创新落在仪器与测量，若保持当前融合框架/位置精度主叙述，直接改名后投TIM并不理想。[GPS Solutions范围](https://link.springer.com/journal/10291/aims-and-scope)、[TIM作者范围](https://ieee-ims.org/publication/ieee-tim/information-authors)。

更合理的论文结构是**一个核心方法贡献、误差或失效模型、完整验证**，无需强凑三个平行算法。现有工作可表述为“紧凑足式平台短基线航向的可信使用及其在本体辅助导航中的条件收益”；这只是准确定位，不代表已经弥补方法创新。

若只做一项AR研究，建议针对**本体先验失效时的短基线整数验收、撤销与再固定**。要回答的是：在两端绝对位置都FLOAT、共同载波仍有信息时，能否产生可信相对航向，并避免坏先验把错误整数持续锁住。长度约束、IMU先验、LAMBDA与动态同步已有直接先例，不能单独作为新点。

一周首先用于资格审查：当前raw对照仍有几十度角误差，Jan5 RAWX还有约7–8ms局部时标差待解释。先把信号、时钟、几何、周跳/半周、协方差和先验独立性闭合；不要重贴时间戳或用强姿态先验把错误模型硬拉回参考方向。过门后才做“标准约束AR / 默认先验可信 / 可撤销先验验收”三支对照。固定率必须与错误接受、可用率和再固定时间一起报告；没有整数真值时真实错误固定率为NA。完整路线和否证条件见[单项AR与期刊定位](04_HEADING_AR_AND_VENUE.md)。

## 4. 数据够不够：够发现问题，尚不足以支持广泛泛化

本次提供的ZIP和8个body与R5已使用文件的完整哈希一致，不是新增验证。仓库并非仅一个录制日：主三窗口为2026-03-06，NMB/XB为2026-01-05；一月还包含8个不同时间session及两个原始位置空间簇。但这不能证明八条独立路线，也不能自动把已分析/已参与研究选择的记录称为盲测集。

现有数据足以做机制分析、状态分层、不同日期的参数转用和失败边界检查。它尚不能支撑强泛化主张：一月NMB存在长缺测大漂移，XB未满足现有航向初始化。失败必须留在论文分母里，不能靠缩短评价窗口让迁移看起来成功。

后续最有价值的新增不是同一路线再切更多片段，而是完整留出一个未用于设计/调参的采集日与路线，覆盖开阔/遮挡、原地转向/侧移、起伏/滑移和实际FIX↔FLOAT转换。若冲刺TIM或AR风险主张，还需独立已知航向/安装几何或合格整数参考。这里没有硬性规定必须多少条路线；关键是主张范围与独立证据匹配。现有数据与新留出数据应分开记账。[原始数据审查](02_DATA_AND_FIX_AUDIT.md)。

## 5. 垂向和D62退化如何解决：用单因素试验检验，不承诺调参必好

前一候选M2只约束body前向/右向速度，第三轴没有测量行。原始SDK z并非零填充，足端粗代理提供有限内部支持，同时存在偏差和明显尾部冲突。本轮只增加第三轴形成M3，保留xy、基础噪声、时序、初始化、比例系数，固定sigma_z=0.132838m/s，不根据评价参考校准或挑选权重。

该试验能回答“缺第三维速度约束是否是垂向失效的重要因素”，不能证明SDK z是真值。即使垂向改善，frame/物理点、时间误差、共享IMU相关性和真实滑移仍需验证。D62水平退化是否改善也由结果决定，不能在测试前承诺已解决。

本轮已完成六组可评估新运行和六次离线评价，另外六组旧结果按哈希复用。首次M3完整传播后被旧二维计数合同拒绝，未输出NAV/STD，记录保留；技术修复后重新冻结，总solver调用数为7，没有按指标调参或删结果。完整来源见[本轮试验结果](06_PILOT_RESULTS.md)。

下表为同一BY2的固定20秒故障窗，单位m，M0为10月4日诊断基线而非重新运行的论文原V3：

|条件与指标|M0诊断基线|M2二维body速度|M3增加第三轴|
|---|---:|---:|---:|
|全GNSS失效：水平RMSE|58.292571|0.836635|1.246703|
|全GNSS失效：垂向RMSE|5.118368|7.126477|0.634415|
|保留航向：水平RMSE|0.702330|0.748108|1.158182|
|保留航向：垂向RMSE|7.151547|7.122955|0.637321|

结论是**第三轴显著缓解垂向误差，但没有同时解决水平问题**。M3相对M2的D61水平误差增加49.0%，D62增加54.8%；相对M0，D62水平误差增加64.9%。所以不能把“加第三轴”直接作为推荐修复，更不能承诺调参后一定全面更好。

H20的yaw RMSE为M0/M2/M3：2.488925/1.902952/1.893358°；而各自C00的同一时间窗已为2.196709/1.769082/1.761616°。因此航向来源中断的附加惩罚约为+0.2922/+0.1339/+0.1317°，M2比M0少约0.1583°。这是有限的航向连续性收益，不能将原本已存在的正常误差差异全部归因于抗失锁，也不能据一个事件证明稳健泛化。

目前没有经过验证的“同时保住D62水平并改善垂向”的替换方案。若未来继续这个工程方向，先闭合SDK frame/物理点、z偏置、时间和共享IMU相关性，再检查第三轴怎样通过状态交叉协方差和共同质量权重影响水平更新；这些是待检验原因，不是已经定位的唯一根因。未经标定地增加第三维或继续扫R，不构成解决方案。原V3保持不变，当前不将一整周投入此分支。


## 6. FIX门应该怎样改：分观测质量处理，不一刀切放开

FIX/FLOAT是接收机载波解标签，不是整个EKF状态的标签。需要分别看：IMU状态传播、位置/RV更新、双天线航向、初始航向。BY2O的291个第二天线FLOAT历元仍准入第一天线位置/RV，说明不是两机不FIX就全停；当前航向和初始航向对双FIX依赖则是真实限制。

现有位置/RV链并没有统一要求两端FIX；[实际R5输入复核](R5_FLOAT_ADMISSION_NOTE.md)确认四段NMB共有636个GNSS1自身FLOAT历元及167个其他有效定位历元，其位置/RV标志都为有效、yaw为无效。这是输入准入计数，未重新逐次核对EKF接受或证明其定位精度。不能把“代码允许非FIX”当作“非FIX质量已验证”。双天线位置差航向的FIX门目前不能直接删：XB双FLOAT差分长度中位10–45米，实际长度约0.35米；RELPOSNED约2.5–2.94公里，是参考站矢量而非两天线矢量。

正确方向是按不同来源建立有效性、噪声与拒绝规则；原始短基线AR则依据RAW完整性与自身整数验收决定相对航向是否可信，不能先要求两端绝对PVT都FIX，否则排除了最值得研究的工况。未通过质量门时明确不可用或不初始化，不能拿SDK未知坐标yaw、参考航向或伪造固定状态把流程强行跑通。
