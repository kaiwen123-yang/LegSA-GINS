## 每个面板读什么

| 面板 | 内容 | 应读出的信息 |
|---|---|---|

| (b) | 常规行走 88–92 s 的三组同点局部 | 依次对比双位置 IEKF、单位置 IEKF、重新初始化 OiSAM。空间差异以真实厘米坐标显示，不能从全路重合直接推断方法完全相同。 |

| (d) | 大幅运动记录 88–92 s 的三组同点局部 | 沿用既定参考事件窗，比较本段真实位置变化。这个场景名描述记录，不把该 4 s 全部解读为剧烈机身动作。 |
| (e) | 单侧天线遮挡记录完整路线 | 保留完整地理路线，标记 154.945–254.945 s 的 100 s 背景段及空间细节位置。 |

局部的 `East/North offset (cm)` 是从同一个参考位置扣除后的地理坐标，**不是位置误差**。各方法使用相同原点，没有逐方法对齐、拟合旋转、平移错开或放大误差。每场景三组范围相同，横纵方向使用相同物理比例。

## 本轮解决的主要问题

完整路线仍纳入所有八个主配置，但精度辨识交给右侧分组局部。局部每组最多四条曲线，以深蓝本文、黑虚线 Truth、深暖色或青紫色对手配合线型区分。每个局部绘图区约 89.7 mm 宽，完整显示规定时间窗内所有有效点；线条点位、真实缺口和分段边界全部保留。TC-FGO 以深绿长虚线显示，GNC-FGO 使用深洋红实线和稀疏菱形标记，标记稀疏不会删去轨迹线上的点。

R4 的局部源片段完整保存，但固定空间视窗裁掉了其中一部分。本轮视窗由该时段内所有方法点的共同范围决定，只向外扩展。前两条记录的完整局部东西跨度约 5.17 m、5.01 m，遮挡后恢复段约 2.75 m；这些是**空间包络跨度**，不是端点位移或路线长度。当前检查结果是局部有效点裁剪数为 0。图上矩形是对应视窗的真实物理边界，`Detail` 引线帮助定位。

## 物理点和结论分工

左列在相同地理坐标下显示原生导航结果，本文、IEKF 和 OiSAM 为 POI 中点，TC/GNC 为 GNSS1 天线点。因此左列回答“路线覆盖与大尺度形状怎样”，局部回答“在同一物理点的小尺度差异怎样”，不能用左列混合物理点排名厘米精度。原同 GNSS1 的 FGO 定位误差和输出覆盖仍保留在 `SOURCE_MAPPING.md` 指向的完整表中。

OiSAM 的 POI 显示沿用 R4 已核验的自身姿态和已登记杆臂。原 GNSS1 重建校验最大差约 1.32 × 10⁻⁹ m，常规场景与既有 strict POI 输出最大差约 7.51 × 10⁻⁹ m。没有借用参考姿态，没有修改冻结评价指标。

**这张图不能单独说明本文的航向收益。** 充足的 GNSS 位置约束可以使多个方法的位置路线接近，同时其航向精度不同。图 9 继续在六方法共同动态支持上比较航向精度与输出连续性；内部机身运动观测的条件平移作用由相应消融图解释。也不从一个局部窗口推导全程优劣排名。

遮挡诊断沿用上一轮结论：原局部的参考轨迹近静止，并与同时间机载 SDK 速度记录的低速读数一致。新的 228–233 s 是登记遮挡结束后的参考运动恢复段，选窗由参考决定，没有按方法误差挑窗口。完整诊断与 SDK 旁证可由 `SOURCE_MAPPING.md` 追溯。
