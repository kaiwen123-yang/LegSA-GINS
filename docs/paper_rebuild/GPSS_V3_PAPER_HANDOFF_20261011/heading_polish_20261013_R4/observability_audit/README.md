## 为什么能确认不是事后旋转出来的七条图线

本次核对没有止于“逆旋转之后数值重合”，而是检查了以下证据链。

1. **确有原生调用和执行记录。** H6 的六份配置各自保存成功 stdout，例如 `PASS_HARTLEY_H5_NATIVE run_id=H6_YAW_M100 rows=63277`。各自 `RUNTIME.csv` 和原生摘要记录 **63,276 次传播、63,177 次接触更新**及约 2.3 s 的计算时间。[E13/E14；完整六份回执在 evidence/](EVIDENCE_INDEX.md)
2. **在原生估计开始前改变初始状态。** 与运行期 SHA 完全匹配的 C++ `run_h5.cpp` 在初始化阶段生成 `Exp([0,0,-alpha])`，调用 `applyInitialGaugeTransform`，然后才开始输出循环。这个变换作用于姿态、世界表达的速度/位置/接触点及协方差，机体系偏置不变。[E08：307–333 行；E10：1095–1118 行](EVIDENCE_INDEX.md)
3. **每个非零设置都重新逐历元传播与接触更新。** 同一原生源文件 389–430 行逐条读取该 cache，调用 `filter.propagate`、`processContactLifecycle`，再把当时的 `filter.stateMean()` 写入 NAV。[E09](EVIDENCE_INDEX.md)
4. **保留 NAV 来自原生输出。** closeout wrapper 的 `compact_member` 将原生 NAV 原样复制到冻结目录。绘图提取器再复制 px/py/pz，未在生成七份绘图 CSV 时旋转坐标。[E12/E01/E02](EVIDENCE_INDEX.md)
5. **本轮七份 NAV hash 均与各自原始 NATIVE_FREEZE 一致。** 当前 R3 七份绘图 CSV 又与各自原生 NAV 逐历元对应。63277 个时间戳逐个一致，位置最大差仅 CSV 浮点往返的 `1.4210854715202004e−14 m`；绘图 CSV 与 2026-10-11 首次提取文件字节一致。

因此，**7 × 63,277 = 442,939 条已保存状态条目有直接文件证据**。这个数字表示同一数据多种初始化的状态总数，不能用作独立实地实验数、独立采样数或七种方法的数量。

## “理论上相同输入应该重合”是否正确

**如果输入、完整初始状态和坐标约定都相同，确定性估计运行应重合。** 本图故意改变了初始全局 yaw，并按同一坐标变换同步处理世界表达的初始量和协方差，所以 (a) 在原始坐标里出现旋转后的路径是实验设计的预期。

(b) 再消除每份运行已知的初始旋转，将结果表达在同一朝向；此时七条路径应当重合。图上的最大三维位置差约 `1.89e−7 m` 是等变性数值残差，不是对真实地理位置的定位误差，也不能当作本文达到亚微米定位精度。

这里检查的是“改变绝对朝向表达后，相对运动估计是否保持一致”。它不是将七条路线放在一起评选最佳算法；用户记得只做过一两个机器人状态估计比较方法，与这七条初值扫描没有矛盾。

## 对图注和正文的纠正建议

此前只写“七次运行”，没有明确算法、同一次采集、六次新增回放与一次复用主运行的关系，容易让人误认为七种方法或七次独立实测。这一表述需要改正。

建议图注开头改为：

> **同一接触辅助 InEKF 的初始航向等变性检查。** 对同一段 BY2 IMU 与足端接触数据，使用相同参数，以七种初始全局航向表示运行同一估计器；0° 结果复用已冻结的主运行，另外六种设置分别重新逐历元运行。(a) 各设置在其初始全局朝向下的估计轨迹；(b) 消除已知初始旋转后的共同相对路径；(c) 与 0° 运行相比的逆旋转后数值残差。

图的科学职责应限定为 **已知全局方向自由度/等变性质的实现检查和研究动机说明**。七条相互旋转的曲线本身不是新的不可观测性理论，也不是本文航向精度优势的证据。新的航向收益应由本文与对照的误差、观测消融及条件实验来证明。是否保留正文大图，可据它对读者理解外部方向需求的帮助判断，不应以“七次运行”增加实验量的印象。
