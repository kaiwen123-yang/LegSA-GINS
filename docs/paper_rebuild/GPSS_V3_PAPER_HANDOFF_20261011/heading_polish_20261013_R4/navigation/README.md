## 每一列看什么

三行分别是常规行走、大幅机身运动记录、单侧天线遮挡记录。

- **左列(a,d,g)：完整路线。** 每场景只用一幅全路线，纳入本文、单/双位置IEKF的文献/标定参数、恢复后的OiSAM、TC-FGO、GNC-FGO。均保留原生完整有效输出，真实缺口和OiSAM分段边界断线。GNC用紫色实线和菱形标记，与同色单位置IEKF的虚线/点线区分。小方框定位中列。
- **中列(b,e,h)：同一物理点的空间差距。** 全部显示POI中点，采用真实厘米坐标和相同尺度，没有人为将轨迹平移错开或放大误差。前两行仍为原参考事件的88–92s局部；第三行改为228–233s的恢复运动。源片段完整保留，超出所示空间视窗的部分按坐标裁剪。
- **右列(c,f,i)：100s航向误差。** 采用与已认可图9一致的六方法共同动态时刻。常规/大幅运动为40–140s，遮挡为154.945–254.945s。TC/GNC没有自行估计的航向，因此不加一条冒充输出的曲线。灰色是实际遮挡183.94–225.95s；淡蓝是中列空间细节的时间。

**读图重点：** 有充分绝对位置观测时，多种方法的路线在米尺度上接近，但航向误差仍能明显不同。因此主要航向收益在右列判断；不能要求航向更准就必须在完整地图上出现很大的位置分离。机身运动带来的条件平移作用继续由图7解释。

## 遮挡局部为什么原来像点团

原局部199.945–209.945s的参考轨迹近静止。实际原生参考样本首末只移动约**6.13mm**，东西范围约**16.4mm**、南北范围约**7.0mm**；按相隔1s的参考位置差计算，速度中位数约**0.00194m/s**。厘米级估计偏差和轻微抖动自然会显示为点团。整个100s的参考净位移约29.07m，不能代表其中每一段都在走动。

坐标核对仍小于4×10^-9m，所以这不是坐标恢复或物理点转换错误。问题出在把近静止片段称作“运动路线局部”。

本轮仅根据参考定义恢复窗口：在登记遮挡结束后，按1s网格选首个5s区间，要求端点位移≥2m且1s位移速度中位数≥0.3m/s。首个符合条件的是**228–233s**：精确区间端点插值位移约**2.70m**、原生样本首末约2.57m，速度中位约0.386m/s。它应称作“遮挡后的恢复运动”，不是“遮挡期间行走”。没有用方法误差挑这段。

原静止证据保存在`OBSTRUCTION_REFERENCE_MOTION.csv`与`OBSTRUCTION_DIAGNOSIS.json`，正文不再塞入这些诊断数字。

## 不同物理点怎样处理

**全路线是地理概览。** 本文、IEKF和恢复OiSAM采用POI中点，TC/GNC保留其已登记GNSS1天线位置。各输出在同一固定地理坐标轴显示，但没有把米尺度概览宣称为同点位置排名。原同GNSS1 FGO误差与覆盖配表仍单独保留。

**厘米局部严格同点。** TC/GNC没有所需自估计姿态，不用Reference姿态替它们改物理点，也不混入POI厘米局部。恢复OiSAM有自身完整姿态，因此复用已有登记的IMU→POI杆臂和姿态旋转，将它自己的位置和姿态用于显示。

三条记录的杆臂来自原登记变换文件，分别为`[0.03, 0.03−baseline/2, −0.30]m`。检查结果：

- 同一自身姿态重建原GNSS1轨迹，与原记录最大差约**1.32×10^-9m**。
- 常规场景没有输入缺口，与已有严格OiSAM的275个POI输出最大差约**7.51×10^-9m**。
- 没有使用Reference姿态，没有拟合平移/旋转，也没有改写任何冻结精度指标。

详细检查见`data/OISAM_POI_TRANSFORM_CHECKS.json`。
