## 二、原V3怎么保留，故事怎么写

本轮没有改原V3科学源码、原始数据、冻结配置、6468个结果，也没有重新执行导航估计器或正式评价器。正文保留原三序列自然结果与完整失败分母：6185完成、193发散、90无法初始化；588个case不是588次独立采集。原V3故事入口仍为[CURRENT_STORY_INDEX](../V3_STORY_20261004/CURRENT_STORY_INDEX.md)。后来33、135、严格FGO和分段诊断保留自己的版本，不替换原矩阵。

实际BY2/H/O的F04配置各175键：153相同，22处只涉及身份、路径、窗口或初始化，没有发现按H/O重新拟合的全局数值参数。因此可以写BY2数值开发后转用。历史记录同时显示H/O参与过方法角色选择，BY2O参与过准入策略选择；这与逐序列数值重拟合不同，却限制了“完全未看过/未参与任何开发决定”的说法。正文已经分别解释，不以此推翻原结果。

论文正文用描述性配置名称，F04等内部代码放映射。LegSA-GINS暂保留为项目标识，正式方法名称尚待作者讨论。论文贡献依据是条件航向、辅助速度依赖、完整正负结果与失败边界，名称本身不构成创新。

原basic→gated对照同时改变receiver velocity与heading treatment，不能单独归因给某一个模块；独立效应用真实同分支单开关消融解释。自然序列的小RMSE、受控故障矩阵和新增诊断各回答不同问题。正文写出了水平收益伴随垂直/航向负效应，保留差结果。

## 三、横向验收的结论

30个读者身份中18个有真实执行链/条件或输入诊断，12个未准入；它们不是30篇论文。按选定链验收15 PASS、3 PARTIAL、12 BLOCKED；按更强的完整作者实验/传感器等价验收18 PARTIAL、12 BLOCKED。这不意味着真实运行不存在，而是不能把工程实现说成所有作者实验完全复现。

对67条条件/支持索引，完成3316项身份与支持检查，并独立从保存的误差重算313项RMSE，均通过，最大差约1.42e−14。67不是本轮运行次数，313不是新增算法测试；RTK float、严格FGO共同支持等未重算范围另有明确记录。

严格一次初始化OiSAM在BY2/H/O正式支持为275/275、0/271、55/378；后续固定连续块分段的主动态支持为275/275、267/271、370/378。两者不能拼成一张最佳成绩表。Wen/GNC没有自行估计的航向成绩，不补造空白。RTKLIB四条件、EXT最新九条、LC各分支、GINav、官方接触InEKF和SDK诊断均有单独身份。表中差成绩可保留用于说明**这些输入和实现条件下**的表现，不能仅因未故意弄差就推导算法普遍不适用。

本轮没有新增已证实、必须修改科学代码的核心错误；已经列出Oi缓存/触发、Wen AHRS接口、GNC公式/Doppler等具体未闭合边界。接下来按这些具体问题查证，不再以“方法数量多”替代复现完整性，也不盲目恢复已取消候选。

## 四、新数据有用，但八段用途不同

8份机身txt共约982MB、49,718,334行进行了完整机器流扫描，解析671,872个带时间戳块；这不是逐字人工审核声明。ZIP没有全量解压。8个唯一采集配对已确定，精密跨设备同步尚未据此成立。

|候选组|实物数据证据|合适的下一步问题|
|---|---|---|
|nmb1–4|有双fixed支持，分别771/1830、750/1805、904/1916、697/1780个有效HP配对|在冻结参数和已声明对时/初始化条件下检查有航向支持时的转用；fixed不等于无误差|
|xb1–4|四段全部无双fixed支持，仍有真实相位/伪距/Doppler|检验自然航向不可用、初始化资格和失效边界；不能临时放宽BOTH_FIXED来取得成绩|

全部16 GNSS raw共29,558条RAWX、32,687条SFRBX通过长度/checksum检查，890,619条实际观测字段已统计。原始双流binary-exact TOW配对为0，局部时间差约毫秒级；RAWX本地近似GNSS时标与HP/PVT iTOW不是同一种时间身份。这说明后续相位方法必须明确异步/clock处理，不等于宣布没有可用GNSS。

机身实际平均捕获约221–235Hz，中位dt约4ms；存在4个超过100ms的gap和7个EOF不完整末块。后续导入必须按真实dt/完整消息处理，不能把它们当完整500Hz记录或填补缺失IMU。当前未修改任何原文、未导入求解器。

8txt和16 raw的24个hash全部命中旧XB_PG登记，且不同于原V3三序列源。因此它们是尚未纳入正式V3矩阵的归档候选，不能自动叫“从未接触的盲测”。场景、控制方式和过去开发角色仍需对应原记录确认。

## 五、安装、时域与TIM模型推进到了哪里

作者确认：相机侧朝机器人前端、CAD对应采集时同一结构、对时看接收机位置/速度与机身IMU。已记录这些事实，不再把Fixposition融合轨迹说成对时信号。单个启动动作只能约束含输出/响应延迟的有效起点差；无法同时辨识clock offset、drift和latency。

教程0.35m是名义套件几何，1m基线下0.4°是厂家规格；CAD组件原点距离不是天线相位中心距离。既有base→FP的0.275m是占位值，不能写成校准外参。供给URDF与xacro的IMU固定坐标也有不同定义，官方SDK未完整给出机器人报告velocity的物理frame/点位语义。

八段实际userio中2955条POI/VRTK变换全部为零平移和单位四元数，支持这八段的配置输出点同一；这项证据不回贴BY2/H/O，也不等于测出了天线/Go2 IMU外参。原始记录支持参考包含视觉、惯性和GNSS融合，但与本方法共用GNSS来源，所以正文使用commercial fused reference/shared GNSS lineage，不写独立真值。

TIM正文和证据文件已经建立基线方向、点位运输、时钟、SDK速度以及参考差值的联合协方差模型，并明确交叉项与重复计数风险。23项输入预算有来源、敏感度和补证方法；没有依据的标准U没有填数。RMSE、工作R、3cm配置要求都没有改名为已校准的不确定度。

## 六、下一步按什么顺序做

1. **以GPS Solutions稿件为主推进。** 中心问题是短侧向基线位置解航向何时有用、动基线/载波路线与它有什么输入和支持差异、辅助速度何时互补或失效。V3本身不解整数模糊度，不能换名成新AR方法。主图由另一个绘图对话接手；本轮已给交接。
2. **补最影响结论的物理事实。** 优先旧三序列的逐段事件/offset记录和实际输出点、实际天线相位中心与Go2 IMU连接、SDK速度坐标/物理点。需要真实量测的地方不能用CAD猜；先补这些，比重复6468次更有信息。
3. **八段候选先登记接口和时间合同，再决定真实运行。** 保留所有八段、原分母、完整消息规则及gap策略，明确无A1时是无法初始化还是已有独立合法初始化。对时只用接收机P/V与机身IMU，不按参考误差选offset。场景/既往开发角色和每段事件记录仍有待具体事实。
4. **针对性补横向原文差异。** 先处理可取得的具体算法/接口证据，再确定是否需要最小修正和新身份运行。完整作者材料缺失时诚实保留实现层级；不通过更换标签伪装复现。
5. **TIM作为计量深化路线。** 按23项预算的影响和可识别性，优先实测时间/外参/参考相关性，再做相应传播与验证；未形成实质测量贡献前不靠改题目重复发表同一研究。

两刊当前均还需图表最终制作、作者信息/声明、文献与正文最后一致性，以及与主张相匹配的物理证据。GPS已核定的Word篇幅和格式通过不等于这些事项完成。[官方期刊要求和来源](sdk_and_metrology/GPS_SOLUTIONS_POSITIONING_AND_REQUIREMENTS_20261005.md)中同时保留实际投稿前需澄清的公开手稿政策措辞；本轮未联系编辑或执行投稿。
