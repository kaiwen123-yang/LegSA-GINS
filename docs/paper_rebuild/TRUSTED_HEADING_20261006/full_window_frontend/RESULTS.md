## Active / pending 与拒绝原因

207 是 **pending provider 构造数**，只有54个不同来源提升为 owner。owner 侧653个 valid 才进入 CSV；pending 侧另有178个内部 valid 步，不能相加为输出覆盖，提升当槽也不导出。三窗共有105个 `source_change` 行；另按事件计54次提升、53次 owner 退休，两个动作可能同槽发生，因此不要求事件和等于行数。退休原因保留为 `PHYSICAL_SUPPORT_INSUFFICIENT` 或 `TTL_OR_PHYSICAL_TERMINAL`，不把 TTL 或资格退休叫作物理周跳真值。

当前诊断共 **5631 GLS、5631 GLRT、5631 geometry、2408 Python sphere ML**，source/slot exceptions均0。按 provider-slot 计，owner/pending 分别出现66/680个多类槽、59/250个空域槽、247/777个质量拒绝槽；两个来源可同历元计算，不能将这些数当4605历元互斥分区。兼容 class-slot 的相位 GLRT 显著标志为221 / 836，仍是工作模型下诊断，不是独立已知故障标签。

70 个当前 sphere 点因完整 raw cost 超出原 tau 被拒（owner24、pending46），说明自由中心/长度必要域不能替代实际可行点核验。另有2个 pending 步因共同 origin 改变重置验证；没有用每槽不同的唯一类拼成五槽通过。详细分母、角色和非互斥原因见 `DIAGNOSTIC_REASONS.csv`。

所有653个导出点的五槽 receipt 已只读核对：来源可用时刻不晚于该逻辑当前槽、原 selected_at 未改、五个实际已存成本各不超过原阈值、共同 origin 非空、模型时间与CSV当前时间相符。这里只核封存身份和数值比较，没有重解；仍保留 `integer_truth_known=false`、`production_validated=false`、`false_fix_probability=null`。

## 工程判断与交付边界

完整窗口证明这条“完整源集合→物理弧生命周期→连续五槽条件点”的前端能够有限成本跑通，且显式保留空、多类、当前质量拒绝、临时cost拒绝与来源切换。覆盖仍低且存在长中断，不能把完整执行等同于可信航向目标完成。接下来的导航效果必须另跑已登记 C++/评估合同，本记录不预告改善，也不改门追指标。

JSON中保存的 geometry 宽度是**兼容 class-slot 的条件方向域宽度**，包括没有发布的类别；不是航向误差、RMSE或已标定置信区间。点协方差仍为固定整数 GLS Cb 加登记 floor，未覆盖离散错整数、选择条件化和未知时域相关。

本目录只保留小表与回执；完整source/slot gzip、4605行provider和逐槽日志仍在原sealed scratch。6个大payload各只做一次流式读取，并在同一读取过程中计算压缩字节SHA；没有重复 whole-payload hash、重跑kernel、读参考/PVT/raw或执行新的NAV。精确别名、字节数、hash及复核脚本身份见 `READOUT_RECEIPT.json`。
