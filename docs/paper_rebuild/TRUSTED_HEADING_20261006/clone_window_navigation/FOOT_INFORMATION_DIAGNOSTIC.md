这里的 weighted trace 使用初始化时冻结的 current21 分块权重；它不是角度标准差。日志的返回 bound_score 在选择 SKIP 时本来就保留 prior_score，epsilon=0 表示动作 SKIP，不是尝试过 epsilon=0 的更新。因此不能将“bound−prior=0”读成五个候选都刚好持平，也不能推出具体拒绝余量。

根据封存算法逻辑，只能进一步确认：在本次实际 P/H/R、固定权重、五个 epsilon 及近似相等优先 SKIP 的规则下，没有候选被选择为足以降低 current21 加权 trace。每个 epsilon 的候选分数、actual P/H/R、信息特征值均未保存在这些事件表里。因而当前记录不能单独区分工作上界过保守、相对方向新增信息弱、固定目标不愿交换状态方差等机制；这些是需要额外登记证据才能判别的解释，不能当作本次已确认根因。

ALL_NATIVE_SEALED 已记录三窗 NULL/PAIR 的 NAV 和 STD 分别字节相同，符合 0 次实际足更新的预期。本诊断未重新打开 NAV/STD，也未读取参考或评价误差。故不能从本次结果归因任何足测量导航收益；也不能据此否定足端信息本身的价值。

读取与操作边界：一次读取六份 ATTITUDE_CLONE_EVENTS.csv 原始字节，内存核 SHA 与 native seal、解析所有行并做简单描述统计；读 native seal 元数据及两份解释源码。没有运行 filter、CILS、native 导航或 evaluator，没有调整参数、筛选观测、修改封存输出。JSON 保存六份完整 header、来源 SHA、事件处分计数、质量统计、初始失配明细及 seal 中的对照字节身份。
