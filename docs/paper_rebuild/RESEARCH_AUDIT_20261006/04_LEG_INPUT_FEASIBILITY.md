# 足式速度重建的原始输入可行性检查

本检查在 Ubuntu 22.04 WSL 执行，只读三条主序列的 Go2 原始日志。不读 GNSS、商用参考或导航输出，不运行导航求解器。目的仅为判断已有数据是否足以支持一周的本体速度工作。

## 固定方法

在既有 BY2/H/O 时间窗中，每隔至少0.2秒读取一个消息；检查时间、角速度、RPY、SDK速度、四脚力、脚位置和脚速度。每时刻固定选择力最大的两脚作为**未经验证的接触假设**，计算 `v_i = -foot_speed_i - omega cross foot_position_i`，两脚取均值。未去除陀螺零偏，未调整阈值/坐标以追求参考精度。比较两个预先列出的接口解释：SDK速度直接作为机体系量，或作为 odom 量经机器人 RPY 转机体系。

|序列|采样记录/完整有限|机体系假设与足端代理差中位(m/s)|odom假设与足端代理差中位(m/s)|两脚差P95(m/s)|
|---|---:|---:|---:|---:|
|BY2|1352/1352|0.0842|1.6889|0.6752|
|BY2H|1333/1333|0.0860|1.6541|0.8215|
|BY2O|1854/1854|0.0591|1.3910|0.5769|

全部4539条采样都具有非零脚位置/速度数据。该比较给出 body 假设的内部一致性线索，也表明脚间差异不小，不能无条件把所有脚等权融合。采样最大间隔 BY2/H/O 为0.218/0.212/0.526秒，实际更新必须尊重缺口与源时刻。

## 能得出的结论

已有日志含实际脚端与IMU数据，不只是厂家最终速度。因此，一周内开展接触筛选、脚间一致性/滑移降权以及GNSS独立运动学速度的受限原型有数据基础。直接使用SDK速度的body残差是较小工程步骤；显式足端速度模型更接近用户提出的足式里程计，但仍需坐标、导数语义与物理点位审查。

## 不能得出的结论

上述差值不是速度精度或独立验证，三个来源可能共享内部估计与IMU。top-2力不保证足端静止，摆动/打滑可使约束失效；SDK脚速度是相对导数还是已做运动补偿仍须核对。没有原始关节编码器正运动学重建，不能声称完整独立腿里程计。结果只说明输入可行性，未调整既定候选试验的噪声、帧或门限。
