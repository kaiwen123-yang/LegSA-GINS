# 四段 NMB 现有输入的速度模长时间诊断

四段数据均存在约 **1 s 的有效时间差**：机身速度变化在记录时间轴上晚于 GNSS。固定共同支持下，相关曲线有清晰内点峰，零延时较峰值低 0.092–0.187。现有 `offset=0` 对两路动态共同变化仍有明显残余错位；本诊断没有确定该差异来自硬件时钟、接收机解算延迟还是 SDK 数据链，也没有将峰值应用到输入。

正 lag 的定义是 `corr(speed_GNSS(t), speed_HV(t+lag))`，即 HV 的相应变化出现在较晚的记录时刻。峰宽为包含最大值且 `r >= r_max − 0.02` 的连续 lag 区间，属于描述量，不是置信区间。四个峰均未触及 ±5 s 搜索边界；按预定描述规则，四条曲线均非平坦。

日期均为 2026-01-05 UTC。完整 UTC 秒和原机身文件起止时间保存在 `TIMING_SUMMARY_4.csv`。NMB1 派生 HV 比原机身文件少末端不完整帧，原始末时刻为 11:22:53.671833；其他微秒量级时戳转换差异保留在表中。

计算使用 `GNSS18.gnss` 的第 7/8 列（零基）水平速度和第 16 列速度有效标记，HV 需同时 `valid=1`、`update_flag=True`。搜索网格固定为 −5 至 +5 s、0.02 s，共 501 个 lag。主曲线始终使用同一组 GNSS epoch；HV 仅在相邻原记录都有效且间隔不超过 0.1 s 时作线性插值，禁止跨无效记录、跨时域边界或外插。最少要求 30 个共同 epoch 和 10 s 支撑跨度。本次四段的固定支撑跨度为 337.6–355.0 s。另列每个 lag 的可用支持数量及其相关系数作为次级信息，主结论没有根据不同支持挑峰。

水平 yaw 旋转保持速度模长；A1 航向可用性在现有 HV 构造中影响有效支持，roll/pitch 投影和物理测量点仍可能影响模长。四段有效 HV 仅约 33%–44% 的派生记录，本结论适用于这组已有效准入的数据，不是整个机身时域的硬件对时验证。约 1 s 相关峰本身也不能证明它解释了定位输出的大误差。

运行 `python3 profile_nmb_speed_lags.py` 可复算两张 CSV 与 JSON；`python3 plot_saved_speed_lags.py` 仅绘制已存 CSV。8 个准备输入文件及既有机身时域汇总的 SHA-256 在读取前后完全相同。新增 estimator/native/evaluator 调用均为 **0**，参考读取为 **0**，输入和参数修改为 **0**。
