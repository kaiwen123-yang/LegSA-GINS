## 输入与模型的选择链

1. **先区分 IMU 加工与尺度。** P03 的 V2i、V2s、V2is 是不同加工/尺度条件；一次 BY2 的前 1000 样本重力范数归一化得到 `s=1.0308398903907543`。它采用 current-sample 增量及冻结序列化，不能同 EXT05C 的 previous-sample 零阶保持视作同一输入。历史 V2e 失败保持 unavailable，未用其他结果填补。
2. **再冻结有效过程先验。** P06 在 BY2 一次计算 q/c 与四段完整 60 s 的 bias 统计，将同一 s、VRW、abstd 转移到 BY2H、BY2O；H/O 没有重拟合。输入是 GNSS1 PVT 速度差分、Go2 roll/pitch 和 A1 航向约束，不读取 commercial 融合参考。q/c 包含运动、映射与传感误差，不证明纯 IMU 噪声可辨识；安装杆臂/时轴属于声明的工程合同，没有由此变成独立实测标定。旧审计将 Git 源文本文件名误判为 trace 读取后只修审计说明，原数值不重算。
3. **验证航向来源和采样。** T5a 初版三次 YAML 往返配置破坏冻结 flat-parser 表示，科学上不接纳；T5a-R 改为只替换 gnsspath 一行、逐项验收静态回显后，16 native /32 evaluator 完成，历史失败不抹去。R1、R1F、R5、R5F 展示 status 与 raw、fixed 与 float 支持差异；GNSS1/2 HP 精确 iTOW 配对产生 R5。
4. **保留未选模型。** T5bc/B3 是三维基线候选，另有 R5σ 与 R5W。BY2 的 1 s 模型残差 sigma `2.026119195812087°`、k `0.40311929221090503`、k_b `0.4350071485556226` 转移到 H/O，而 H/O 的对应统计只诊断。B3 用 0.35 m 模型长度，但评价点转换仍用各序列冻结长度。初版 D57 分类前缀硬停，续作只按授权修控制与 bookkeeping，261 native /494 evaluator 达成终态。B3 单基线轴旋转不可观、D30–41 sidecar 不接受原直接航向注入、HV 仍继承旧扰动；它不是原 V3 全矩阵的三维航向版本。
5. **选定原 V3，而非继续择优替换。** 既有三序列 F04 yaw RMSE 之和 R5 `6.2538569227651107°`，R5σ `6.1442162463454558°`，R5W `6.1050993524129546°`；后两者改善 `0.1096406764196549°` / `0.1487575703521561°`，均未达到当时 0.3° 的事实核对条件。61 例旧 F04 有限 60、R5 有限 58、共同有限 57；R5 在旧完成的 D27/D57/D60 上失败，也在旧失败的 D37 上完成，全部保留。该 0.3° 不是后续矩阵筛选阈值。
6. **有效性规则来自明确的历史选择。** 以已存 BY2O 主段 `[3369.94,3411.95]` s，F04 R5 的 yaw RMSE 为 `0.2325140820805299°`，R5F 为 `1.0351701650068426°`，按先定规则选择两接收机均 fixed，即 NAV-PVT carrSoln 都为 2。这里用到了同一采集活动已有结果，论文应披露开发/选择历史；不能称选择前完全未见的独立测试集。

因此，最终原 V3 应写成：**同一闭环误差状态 EKF、同一一次冻结过程先验、同一 RD/RP/HV 源文件，直接标量航向改为精确配对的 5 Hz 双 fixed raw 基线流；源感知权重对六类观测作保守 R 膨胀。** 姿态状态、RV、RD、RP、HV 与质量/有效性含义见 [第二块](02_METHOD_CONFIG_METRIC_STORY.md)。不把“腿”写成实际足端 FK/接触因子，不把原 V3 写成 FGO 在线反馈。

这条演化只改 GNSS18 的 yaw 与 yaw_valid；随机航向故障是旧 1 s 已实现扰动在 `[t_i,t_i+1)` 的延拓，不是独立 5 Hz 噪声重抽。std 标记仍 `2.933193` 及原各行故障 token；HV 仍用原 status/A1 旋转。D40 的基线长度/rel-acc 元数据没有原标量 solver 通路，不用该类型证明三维基线因子鲁棒性。D55/D56 是源元数据作用，不是接触运动学实验。

## 与旧v2.1失败计数的边界

原V3自身283算法失败是实际封存结果；旧v2.1的177来自其原条件与分类口径。FC01曾计划统一跨链分类，但因用户当时规定“CORE任何F01 NAV哈希不同即硬停”，发现54CORE和18A2差异后没有执行统一分类或新汇总。54是轨迹字节hash差异数，不是54个算法失败。已读输入审计证实非yaw/valid字节及实际IMU不变；关闭在线yaw不屏蔽yaw_valid参与事件调度/IMU增量拆分，不能据此期待每个NAV必同hash。该路径是支持的可能机制，并非唯一原因证明。

这段历史保留用于防止把177→283直接写成性能恶化/提高，**不改变原V3的正确执行身份，不引申新的纠错要求或重跑目标**。旧资料中的“v2.1唯一论文链”描述各阶段当时的授权，当前原V3故事以本次用户明确范围与上述原freeze为准。
