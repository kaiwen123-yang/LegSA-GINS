# 载波相位与动基线模糊度开发

本轮已从单星观测检查推进到 **GPS、Galileo、北斗三系统双频的真实动基线整数求解**。所有算法修改、数值试验和原生转换均在 E 盘 Ubuntu 22.04 WSL 完成。当前交付是可运行的研究前端；论文不是本轮工作，V3 主算法和旧结果保持原样。

## 已实现

- **单信号观测与连续弧**：明确载波单位、波长、GNSS2−GNSS1 符号；处理失锁、缺测、半周状态、时钟重置与相位/Doppler不一致。单颗卫星不被当作完整三维基线解。
- **时序动基线 C-ILS**：连续弧共享整周整数，每个历元独立估计三维基线并满足给定长度。机器人转动时不会被强制静止。完整历元内双差协方差进入求解。
- **多系统多频模型**：GPS L1/L2、Galileo E1/E5b、北斗 B1I/B2I 各保留信号组、参考星和整数基底；可输入跨频完整协方差。无偏差模型的 GLONASS FDMA 暂不进入整数模型。
- **当前有效整数判别**：旧弧整数继续参与历史目标，但最佳、次佳按当前有效整数分组；解决两个候选只在已失活卫星上不同、无法判别当前测量的问题。
- **未来历元检查**：固定已选整数，只估计未来每历元基线；遇到新弧则剔除依赖未知整数的相位行，并正确取协方差子矩阵。只在双方共同成功评分的相同观测支持上比较。

源模块位于 src/legsa_gins/paper_rebuild/carrier_phase/，入口脚本位于 scripts/paper_rebuild/carrier_phase/。107 项自动化测试通过，包括独立小规模穷举、非平凡整数基底变换、动态基线、整周周跳、完整协方差、整数溢出及缺失未来支持。

## 实际结果

| 检查 | 结果 | 能说明什么 |
|---|---|---|
| 10 个固定新噪声实例，名义 1/5/10 历元 | 正确整数分别 6/10、9/10、10/10 | 当前模型中，积累动态相位信息有收益；不是总体固定成功率 |
| 合成压力试验 | 共 48 次执行；正确新弧周跳 3/3 恢复；漏分弧三例模型不相容；0.25 周偏差仍可选错或损害基线角 | 弧管理和非整周偏差仍决定可靠性 |
| BY2 80–82 s | GPS L1、GPS双频、GPS＋北斗双频；9 次完整整数比较＋6 次当前整数类比较 | 15/15目标优化证书；该窗口没有因果可用Galileo完整星历 |
| BY2 100–102 s | 实际六个组：GPS L1/L2、Galileo E1/E5b、北斗 B1I/B2I；同样15次求解 | 三系统双频真实链路运行成功，15/15目标优化证书 |
| 两窗当前整数类的未来检查 | 共6组，每组后续5历元，原最佳候选残差均低于备选候选 | 在相同后续观测上有判别力；真实整数真值仍未知 |

两窗合计 **30 次真实整数搜索、20 次冷启动码 SPP**，无融合参考输入；均为同一 BY2 录制的开发窗口。78 次注册求解由48次合成和30次真实组成，不包含自动化测试内的小求解，也不是78个独立样本。

所有真实搜索都在注册的60秒/100000节点上限内结束。单次耗时0.020–50.690秒，依问题而变，不能据此称为实时实现。给定基线长度为名义0.350 m，未在本轮进行机械长度标定。

## Galileo 修复

原始文件有 Galileo 相位和导航页，但旧 RTKLIB 转换器的一条长度判断跳过了有效8字 I/NAV。新转换器在独立构建中只修这一判断，保留最小长度、CRC、IOD、卫星编号和健康检查。只使用 E1B 导航页组装 Galileo 星历，避免不同信号页混装。

输入检查表明完整健康页在约99.398秒才收齐，因此事前选择100–102秒窗口。V2所用的两份新导航文件仅由截至100秒、最后RAWX为99.998秒的原始流前缀生成，保留GPS/北斗导航；没有加载旧的全文件导航。不能把这次修复回填到80秒并称为因果首次固定。

## 工程判断

继续载波方向有依据：已完成从原始观测、真实导航电文、动态时序整数到三系统双频的运行链路，也观察到同一批已知真值实例的时序收益。接下来的重点是非整周相位异常隔离、当前整数的统计验收和连续运行效率。现阶段所有输出仍明确标为实验候选，不向V3 EKF自动注入可信FIX。

## 运行入口

在Ubuntu22.04中使用当前源码的 PYTHONPATH=src，设置 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1。

1. real_trial.py prepare --roots <local-roots> --output <new-trial>：独立原始接收机配对、弧和模型；V2另指定 --start 100 --stop 102 --navigation-manifest <causal-nav-manifest>。
2. real_trial.py solve --output <trial>：1/5/10历元完整整数比较。
3. real_trial.py solve --output <trial> --active-classes --prefixes 5 10：当前整数类比较。
4. future_checks.py --trial <trial> --output <new-future-dir> --solve-directory SOLVE_ACTIVE --prefixes 5：随后五历元检查。
5. prepare_navigation.py --help、synthetic_trial.py --help：独立转换与已知真值试验。

输出目录需要新的身份；脚本拒绝覆盖已有实验。原始数据及派生数值大文件不提交Git，小表、源码和复核结果已提交。
