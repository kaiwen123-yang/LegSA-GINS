# EXT execution and Git preservation identities

This checkpoint preserves the completed nine V2 native executions, their three offline evaluations, and the later projected-heading boundary guard. It performs no new solve, evaluation, parameter selection, or result replacement.

The completed V2 run source identity is the pinned overlay in `v2_fix/FINAL_EXECUTION_RECEIPT.json`, not the date of this later Git commit. The three later guarded source files are explicitly bound in `post_result_heading_guard/EXT_HEADING_POST_RESULT_SOURCE_CHANGE.json`; the old nine runs did not execute that guard. The stored 9,100 valid projected headings do not trigger it. Frozen receipts retain their statements about commit status at capture time.

Large per-epoch native and offline payloads remain local under the documented native stage and `v2_fix/native_results` / `v2_fix/evaluation_results`. This checkpoint tracks code, configuration, small summary tables and review receipts only. Original V3, RTKLIB, moving-baseline and LC01 were not rerun. Poor EXT scores remain reported; projected baseline azimuth versus commercial fused Euler yaw is a disclosed measurand limitation, so those scores alone do not establish universal unsuitability.
