# Addendum native identity transport

This implementation companion records a loader compatibility mapping for the pre-registered A1/A2 addendum. It does not alter the addendum contract, frozen executable, evaluator, degradation parameters, method profiles, seed policy, or statistical definitions.

The frozen loader in `cpp/legsa_v23_port_core/src/config/port_config_loader.cpp` accepts five-digit `RUN_` identifiers and only `C00_clean_normal` or `D01`–`D60` seed tokens. Its native `C00_clean_normal` token requires `data_mode=real_clean`; a degraded native token requires `real_base_controlled_degradation`. The locked executable cannot accept the addendum's `ADD_RUN_*` or `D61_*`/`D62_*` identifiers directly.

The authoritative scientific identities are the outer addendum registry: `ADD_RUN_00001`–`ADD_RUN_00495`, the exact `D61_10s_seed_00`-style family/duration/seed identifiers, and the eleven frozen method profiles. These uniquely identify 495 newly executed addendum runs. Their data classification is `data_mode=semisynthetic`, `synthetic_data_used=false`, and `semisynthetic_data_used=true`.

The native loader receives the reserved tokens `RUN_06001`–`RUN_06495` in the same order, with matching `run_label`, `D01_seed_00`–`D01_seed_08` preserving the registered seed, and its supported `real_base_controlled_degradation` schema token. `native_case_token_has_scientific_meaning=false`. A native `D01_seed_*` token does not denote a core D01 degradation, a core run, or core evidence. There is no native C00 replay or parity claim. No core result is reused or substituted.

Only native `run_id`, `run_label`, `case_id`, and `data_mode` lines are mapped before the existing CAL adapter runs. The adapter retains the frozen native stage, protocol, role, algorithm and enable flags; binds the actual generated addendum inputs and owned output directory; and changes only the previously registered CAL `vrw` and `abstd` parameters. The executable remains SHA-256 `9c00565c45b654453b2b378f3d5995e5dc21d1271323a9b683acdab75993235f`; the evaluator remains SHA-256 `aa0492482b6467cdd701bc8882aca11c4170bbe2e7c6bb5f932679dc204978da`.

Before providers run, `00_PREREGISTRATION/NATIVE_IDENTITY_MAPPING.csv` records all 495 outer/native mappings and the exact frozen runtime-template path/hash for each profile. `CASE_REGISTRY.csv`, `UNIQUE_RUN_REGISTRY.csv`, the committed contract copy and execution freeze accompany it. The contract hash-locks the real base provider roles and seed anchors. Each generated provider records original and resulting source hashes, exact validity masks and unchanged payload checks. Each run records `native_template_transport`, actual provider hashes, actual opened input paths, native identity validation and outer case metadata. This evidence, rather than the opaque native D01 token, determines the scientific case identity.

Native solver outputs and manifests remain immutable and are sealed before evaluation. The evaluation adapter consumes the actual new native output with the outer addendum case metadata and outage interval. Separate addendum manifests and tables carry the authoritative outer identity and data classification. Core 541 tables and existing native/evaluation outputs remain unchanged.
