## 唯一改动与不变项

唯一科学改动：双天线标量航向从 status 航向输入改为原始 HPPOSECEF1/2 精确配对的
5 Hz 航向。使用不改动的 T5a-R `raw_yaw_from_ned` / `build_t5a_variants`，沿用
GNSS2−GNSS1、冻结坐标变换、安装关系及 wrap-safe 标量残差。

冻结二进制 SHA256 为
`96ae436d82ba8922c68382bd73fc42c8bf4bcb22d72a43a8bd05f506043a9c1c`；
冻结评估器 SHA256 为
`aa0492482b6467cdd701bc8882aca11c4170bbe2e7c6bb5f932679dc204978da`。
不修改 C++、任何运行参数、IMU、位置、速度、RD、RP、HV、工况、种子或配置集。
GNSS18 只允许第 14 列 yaw 和第 18 列 yaw_valid 改变；其余 token、空白、行序及时间字节不变。

三序列基准 std 标记仍为 `2.933193`。它是继承的 v2.1 固定标记，本任务不声称
重新标定了 5 Hz 航向噪声或独立性。各注入工况的 std 列逐行保留，包括
D36/D37/D38/D60 原有缩放；旧 1 Hz 航向行与中间行可能有不同 std。
F01 沿用 v2.1 实际复用的冻结 F01 配置和 provider；其不启用航向更新的原 std 字节也保留，
不为统一标签另改输入。不同原 GNSS 哈希分别生成衍生表，不把 F04 provider 替换给 F01。

所有方法及注入工况的 HV 文件均按原哈希复用。其旋转继续使用 status 航向及原注入后的
有效性处理，不用新 5 Hz 航向重建。故 v3 的直接航向输入与 HV 旋转的航向来源、采样和
故障暴露不完全一致；不能宣称整个航向依赖链均已变成 5 Hz。此边界与 T5a-R/T5bc 一致。

## 航向故障在 5 Hz 表上的时间语义

故障参数、9 个种子及已选 anchor 不变。具体逐工况窗口完整列在
`HEADING_FAULT_WINDOWS.md`，来自本次哈希冻结的原 provider bundle。
自然序列使用未注入的原始流；Canonical 和 A1/A2 保留半合成标签，分别汇总。

原冻结航向源在 BY2 有 301 个有效时刻 `56,57,…,356` s。
对已实现的随机角度扰动，先取原 case 输入航向减原基准输入航向的圆周差，
再在 `[t_i,t_{i+1})` 时间单元内加到新原始航向；最后一个单元为 `[356,357)`。
`[56,357)` 外保留新原始航向，不延长末次扰动。不读取任何 solver 输出进行此映射，
不重新抽取噪声、尖峰或事件。它是冻结扰动的时间单元延拓，不是独立 5 Hz 高斯采样。
标量差只用于已登记的故障注入，不是估计输出校正。

native 64 路并行，各数值库一线程。每次 native/evaluator 启动前 fsync 唯一预约，
失败消耗名额，不重试。每 64 项分批留存；新生成 scratch 大文件仅在无损归档、原字节
SHA256 校验完成后按逐项清单释放，保留完整恢复信息与证据；不得触及任何冻结文件或根。
trace 仅由冻结评估器子进程读取一次；provider/controller/native 不读 trace。
绘图所需 Truth 只从同一评估器进程已读取的引用数组观测导出，不新增 trace 读取，
不改变评估器或计算结果。

分类沿用 D12：可确定的算法失败记录后继续；任何身份门失败、非航向差异、二进制或
评估器哈希不等、分类不了的失败立即硬停，不自动改代码续跑。停止时保留已消费预约及全部证据。
并行硬停立即停止新派发并取消尚未开始的任务；已启动子进程允许收束并封存，
不再启动相关评估或下一批。硬停报告列出检测时及收束后的实际消费数量，不把在途运行隐去。
